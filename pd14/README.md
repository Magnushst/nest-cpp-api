# The cortical microcircuit

The model of Potjans and Diesmann (2014): four cortical layers, each with an
excitatory and an inhibitory population of leaky integrate and fire neurons,
connected by an eight by eight matrix of connection probabilities and driven by a
layer specific external Poisson input. It is the second case study in this
repository, and it is the one that decides whether the C++ interface generalises
past a two population network.

## The files

| File | What it is |
| --- | --- |
| `reference/` | The upstream PyNEST microcircuit, plotting removed. The baseline. See `reference/PROVENANCE.md`. |
| `microcircuit.cpp` | The same model written against `nest::api`. |
| `microcircuit_params.hpp` | The parameters and the derived network, in C++. Arithmetic only, no kernel. |
| `check.sh` | Runs both and fails on any difference. |

## The network

| Quantity | Value |
| --- | --- |
| populations | 8, an excitatory and an inhibitory one in each of L2/3, L4, L5 and L6 |
| neurons, unscaled | 77,169 |
| neurons, at the default scaling of 0.1 | 7,717 |
| synapses, at the default scaling | 3,004,241 |
| neuron model | `iaf_psc_exp`, threshold -50 mV, membrane time constant 10 ms, refractory 2 ms |
| connectivity | `fixed_total_number` per population pair, from the 8x8 probability matrix |
| weights | drawn per connection, normal with 10% relative width, redrawn to keep their sign |
| delays | drawn per connection, 1.5 ms excitatory and 0.75 ms inhibitory, 50% relative width, redrawn to stay on the grid |
| external drive | one `poisson_generator` per population, 8 spikes/s times the external indegree |
| initial membrane potential | drawn per neuron, population specific mean and width |
| simulated time | 500 ms presimulation, then 1000 ms |

Scaling the network down thins the input to each neuron, so the weights are
scaled up by the square root of the indegree factor and the lost mean input is
added back as a DC current. That compensation is part of the model, and the
programs reproduce it rather than approximating it.

## The evidence that the translation is right

`pd14/check.sh` passes. Both implementations write the upstream file names, so
each runs in its own directory and the directories are compared whole.

At the upstream defaults, one tenth of the neurons and one tenth of the
indegrees on four threads, 1500 ms simulated: **all 33 output files are byte
identical**, 21,093 spikes across eight populations and four virtual processes,
and the node ID bounds of every population agree. The reported totals agree as
well: 7,717 neurons and 3,004,241 synapses.

On two MPI ranks of one thread each, the same comparison holds: 17 files byte
identical, 20,992 spikes. Both implementations are rank agnostic, which is the
only sense in which a driver can be: every rank runs the same program and the
kernel decides which nodes it owns. Run it with `RANKS=2 THREADS=1 pd14/check.sh`.

That covers the C++ against the Python running here. There is a stronger check
available, and it also passes: the upstream example ships the spike files it
produced when the NEST team ran it, committed alongside the code. Running the
C++ implementation single threaded reproduces **all eight of them exactly**, 833
to 8,507 spikes each, 20,505 in total, together with the node ID file. Those
files were generated by a different program, on a different machine, against a
NEST built from `master@7c40d9e9a`, which is older than the 3.10.0 kernel used
here. The C++ implementation lands on them spike for spike.

## What the network does, and what the scaling costs

Identity to the Python proves the translation. It says nothing about whether the
network is in the state the model is meant to produce, so that is measured
separately, from the spike files, over the 1000 ms after the presimulation:

| Population | Rate at 0.1 scaling | The model's full-network rate |
| --- | --- | --- |
| L2/3E | 0.488 Hz | 0.903 Hz |
| L2/3I | 2.108 Hz | 2.965 Hz |
| L4E | 4.004 Hz | 4.414 Hz |
| L4I | 4.978 Hz | 5.876 Hz |
| L5E | 6.680 Hz | 7.569 Hz |
| L5I | 7.726 Hz | 8.633 Hz |
| L6E | 0.832 Hz | 1.105 Hz |
| L6I | 6.990 Hz | 7.829 Hz |

The right hand column is `full_mean_rates` from the model's own parameter file,
which is what the unscaled network produces. Every population fires in the right
order of magnitude and in the right order relative to the others, and every one
of them fires slower than the full network, most of all L2/3E at roughly half.

That is the downscaling, not the translation: the Python produces these same
numbers, because it produces these same spikes. Scaling the indegrees down by
ten and compensating with weights and DC current preserves the mean input and
the variance of the input, and does not preserve the correlations, which is
exactly the limitation van Albada, Helias and Diesmann (2015) set out. The
model's own README says to set both factors to 1 for the real thing.

**The full-scale network has not been run here.** 77,169 neurons and about 300
million synapses against a NEST built with assertions live is not a laptop
workload. Both implementations take `--n-scaling` and `--k-scaling`, and agree
at every value tried, including 1.0 for the derived quantities.

## The arithmetic has to match before anything else can

The model derives an eight by eight matrix of synapse counts, the population
sizes and the external indegrees from its parameters, and rounds all of them to
integers. Those integers decide how many random numbers the kernel draws. One
synapse more or less in any of the 64 entries changes every spike that follows,
so the derivation has to agree with the Python bit for bit before comparing
spikes means anything.

It does. `microcircuit_params.hpp` reproduces every derived quantity exactly, at
the default scaling and at four others, checked against
`reference/run_ref.py --derived` at 17 significant digits: 64 synapse counts, 8
population sizes, 8 external indegrees, the 64 mean weights, the external weight
and the 8 compensating DC currents.

Getting there needed two things that a direct translation gets wrong, both of
which change the network at the default scaling of 0.1:

* **`np.round` rounds halves to even; `std::round` rounds them away from zero.**
  Population L5I has 1065 neurons unscaled, and 1065 × 0.1 is exactly 106.5.
  NumPy gives 106, `std::round` gives 107. `std::nearbyint` under the default
  rounding mode gives 106.
* **`np.sum` over eight contiguous elements is a balanced tree, not a left to
  right sum.** NumPy's pairwise summation keeps eight partial accumulators and
  combines them pairwise. Summing left to right instead moves the compensating
  DC current in its last two bits, for example 29.035009174000606 pA against
  29.035009174000663 pA for L2/3E.

Neither is a rounding subtlety that can be waved away: the first changes the
number of neurons in a population, and the second changes a current that every
neuron in the population receives.
